## Purpose

Reproducible numerical experiment for the paper subsection *"A state-estimation
illustration on SO(3)"* (`../../ba-sample.tex`, `\label{fig:so3-estimation}`).
It shows that on `SO(3)` the **choice of metric in Definition 5 changes the
estimate an engineer reports**, from **one fixed prior** (`nu_bi`, Haar) and one
fixed attitude sensor, and (via the symmetric run over two heading
measurements) that **the calibrated analyst is always the one whose metric is
the metric in which the heading was measured** — neither metric is universally
right. Every number quoted in the paper and Figure 3 is produced here.

**Design (since 2026-09-28).** Both experiments draw `R* ~ nu_bi`. The heading
is a *gate*: `R*` is recorded only when it lies within `delta` of the slice
`{yaw = yaw*}`, the distance measured in `g_bi` (panel a) or `g_flat` (panel b).
That is the tube of Definition 5, so as `delta -> 0` the exact Bayes posterior
is Definition 5 in the gate's metric. The previous design (prior of `R*`
changed between regimes, heading = `R*`'s own exact yaw) has been removed from
the script (see git history); do not reintroduce it: it had the `cos β` factor
on the wrong analyst (restricting the Haar density is Definition 5 in `g_flat`,
not `g_bi`).

## How to run

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python so3_experiment.py            # full run ~2 min: results.json + figure PDF
python so3_experiment.py --quick    # smoke run (coarse grid, few trials)
python so3_experiment.py --delta-check  # ~6 min: robustness to delta + its supplement figure
python so3_experiment.py --delta-figure # redraw that figure from the JSON, no recompute
```

Repo convention: a venv named `.venv-so3/` at the repo root is git-ignored.
All randomness is seeded inside the script; reruns are bit-stable.

## Naming (one vocabulary everywhere)

The two metrics are named identically in the paper caption, on the figure, in the
code identifiers and in `results.json`:

| object | name | code | JSON |
|---|---|---|---|
| invariant metric `g_bi` | **translation invariant** | `inv` / `p_inv` / `cov_inv` / `metric="invariant"` | `*_invariant*` |
| flat metric `g_flat` | **flat chart** | `flat` / `p_flat` / `cov_flat` / `metric="flat"` | `*_flat*` |

`"isotropic"`, `"geodesic"` and `"flat-Euler"` were earlier names for these and
must not be reused for them. Two literal uses survive and are correct: the sensor
noise *is* isotropic, and `geodesic_angle_to` *is* a geodesic (rotation) angle —
both are shared by the two analysts through the likelihood, so neither names a
metric.

## Code map (`so3_experiment.py`)

- `Rz`, `Ry_grid`, `Rx_grid` — elementary rotation matrices, vectorised over
  angle grids.
- `verify_haar_cosine` — sanity check: Haar density ∝ cos(pitch) in the chart.
- `verify_def5_slice_conditionals` — sanity check of the load-bearing fact:
  thin `g_bi` tubes around the slice give a uniform pitch, thin `g_flat` tubes
  give cos(pitch)/2 (KS distances printed in `[0]`, stored in `def5_slice_ks`).
- `exact_null_set_summary` — closed-form pitch posteriors for the exact-heading
  case (invariant = uniform, flat = cos/2); credible intervals, ±30° band
  probability, and each analyst's coverage when the gate is in the *other*
  metric. **Headline numbers quoted in the text.**
- `slice_rotations` / `geodesic_angle_to` / `posteriors_on_slice` — build the
  posterior over pitch on the slice `{yaw = yaw*}` for both analysts, given one
  isotropic noisy attitude observation.
- `central_interval` — central credible interval of a 1-D density on the grid.
- `slice_distance(R, metric)` — distance to `{yaw = 0}`: in `g_bi`, the angle
  from the pointing axis `b1 = R e1` to the *half* great circle of heading 0
  (to the vertical plane if `b1` points forward, else to the nearest pole — the
  plane alone also contains heading π, which is a different slice); in `g_flat`,
  `|yaw|`. Checked against brute-force minimisation.
- `draw_gated_truths(metric, ...)` — Haar draws kept when `slice_distance <
  delta`, then left-rotated to a uniform target heading `yaw*` (exact by left
  invariance). Returns `(R_true, yaw_star)`.
- `run_calibration(..., metric=..., delta=...)` — Monte-Carlo coverage vs noise
  scale `sigma` for one heading metric. Conditions on the gate's `yaw*`, not on
  `R*`'s yaw. **Panels (a) and (b).**
- `representative_trial` — one trial's posteriors (helper; not currently plotted).
- `make_figure` — writes the two-panel PDF, titled "measurement of α: …": (a) in `g_bi`,
  (b) in `g_flat`. Legend `"lower left"` in both; the "nominal
  90%" annotation is `"upper right"` in (a) and `"lower right"` in (b), where
  the invariant curve climbs above the line.
  **Label vocabulary is load-bearing:** the panel titles and the legend name the
  two metrics in the *same* words as the paper's caption (see Naming above).
- `run_delta_check` — reruns `run_calibration` for three gate tolerances;
  δ = 0.005 rad reproduces the main run exactly (same seeds). Writes
  `results_delta_check.json`.
- `make_delta_figure` — Supplement Figure `fig:so3-delta` from that JSON: same
  panels/colours as the main figure, colour = analysis metric, line style = δ
  (dotted 0.1°, solid 0.29° = main run, drawn thicker and underneath, dashed
  1°); the nominal line is thin solid grey so it is not read as a δ style.
- `main` — orchestrates both regimes, prints headline numbers, writes
  `results.json` + PDF.

## Invariants the code (and the paper) depend on

1. **Haar density ∝ cos(pitch)** in scipy's `ZYX` yaw–pitch–roll convention;
   yaw/roll uniform. `verify_haar_cosine` asserts it (< 5% MC error). If you
   change the Euler convention, re-derive this factor.
2. **Definition 5 on the slice, from `nu_bi`:** `g_bi` → uniform in (β, γ)
   (the `g_bi` tube has width ∝ 1/cos β, cancelling the Haar cos β; the induced
   `g_bi` area on the slice is dβ dγ); `g_flat` → cos β. This is the SO(3)
   analogue of the sphere proposition (invariant metric → uniform on great
   circles). `verify_def5_slice_conditionals` asserts it.
3. **Ground truth = the metric the heading was measured in.** Prior (`nu_bi`)
   and attitude sensor are the same in both experiments; only the gate's metric
   changes. With the `"invariant"` gate the translation invariant analyst is
   exact Bayes; with the `"flat"` gate the flat chart analyst is. If the matching
   analyst drifts far from 90%, that is the bug.
4. **The two analysts differ only in the `cos β` factor.** `posteriors_on_slice`
   applies `cosb` to the flat branch (`p_flat`) and not to the invariant branch;
   everything else is shared and independent of the gate. `delta` (0.29°) must
   stay ≪ the smallest `sigma` (3°).

## Expected headline results (regression check)

Exact null-set posterior of pitch:

| quantity | translation invariant | flat chart |
|---|---|---|
| central 50% interval | `[-45°, 45°]` | `[-30°, 30°]` |
| `P(|pitch| < 30°)` | `0.333` | `0.500` |
| coverage of nominal 90% interval when the gate is in the other metric | `98.8%` | `71.3%` |

(Identical to the sphere numbers of Section 4: 1/3 vs 1/2, [-45°,45°] vs [-30°,30°].)

Calibration (2000 trials/level, `delta = 0.29°`), the symmetric run:

- **Heading measured in `g_bi`** (panel a, translation invariant is exact Bayes):
  invariant 88.5–90.5% at every `sigma`; flat chart 87.8% at `sigma = 3°`,
  falling to 70.2% at `sigma = 90°` (under-covers = over-confident).
- **Heading measured in `g_flat`** (panel b, flat chart is exact Bayes): flat
  chart 88.9–91.0% at every `sigma`; invariant 89.5% at `sigma = 3°`, rising to
  99.1% at `sigma = 90°` (over-covers = conservative).

The mirror is the point: the calibrated curve swaps panels, with the prior held
fixed.

If your change moves these numbers, either it is a bug or the paper text and this
table must be updated together (and re-check `ba-sample.tex`).
